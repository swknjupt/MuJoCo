## 1. Demo 定义与选型理由

> 一句话：一根真实摆杆 + 一个真实电机——RL 策略在 1kHz 硬实时环里控制它起摆并保持
> 直立；故障注入让策略跑飞；governor 拦截并安全接管；全程确定性记录，一键复现。

**为什么是单摆**：

- 它是控制界的 "hello world"：观众 3 秒看懂目标（立起来），失败模式肉眼可见（倒下/甩动）；
- 本仓库已有全部仿真侧资产（`examples/models/pendulum.xml`、SB3 PPO 训练脚本），
  demo 是现有学习路线的自然延伸，不从零开始；
- 物理后果的真实性达到最小可信剂量：真实电-机动力学、真实总线时延、真实编码器
  量化——这三样是仿真给不了的，而摆杆是承载它们的最便宜载体。

**为什么不是别的**（反面清单，与设计文档一致）：

| 候选 | 不选的原因 |
|---|---|
| 仿真弹球 | 仿真时间可暂停、无 deadline、无后果——平台所有卖点在其中**结构上不可能失败**，证明力为零 |
| 整机（四足/人形） | 变量不干净，观众可归因于"整机没调好"；且首个 demo 背上整机集成风险 |
| 灵巧手操作 | 产品定位明确绕开的领域 |
| 实时渲染感知闭环 | 诚实版本是 M4 的 log-and-replay，首 demo 不碰 |

## 2. 总体架构：MBD 六要素各就各位

```
┌─ Host（开发笔记本）──────────────────────────────────┐
│  MuJoCo 训练 PPO 策略 ──→ 导出 ONNX                   │
│  控制台：实时曲线 / 抖动统计 / 一键重放 / 报告生成       │
└────────────┬─────────────────────────────────────┘
             │ 信号字典（角度/角速度/力矩/时间戳/包络状态）
┌────────────▼──────── RT 盒（NUC / RPi，PREEMPT_RT）──┐
│  1kHz 主循环: 读编码器 → 包络检查 → 低层PD → 力矩指令  │
│  100Hz 策略推理: ONNX timeboxed（超时→沿用上次有效输出）│
│  Governor: 角度/速度/力矩包络 → 越界→ 能量法回退+抱闸  │
│  故障注入: 延迟 k ms / 编码器丢帧 / 力矩衰减           │
│  RT 模型: MJCF → 线性化模型（包络预测 + 误差对比用）    │
└────────────┬──────────────────────────────────────┘
             │ RS485 / 实时总线
      ┌──────▼───────┐
      │ 真实电机 + 摆杆 │  ← 唯一的"物理"，全部戏剧在这里发生
      │ （可夹装配重块） │
      └──────────────┘
```

分层要点（与真实机器人架构同构）：

- **100Hz 策略 / 1kHz 低层**：NN 推理耗时有抖动，不进 1kHz 拍；策略出目标，
  确定性 PD 以 1kHz 插值执行——这正是设计文档 §5.1 的 governor 架构微缩；
- **timeboxed 推理**：推理窗口封顶（10ms），超时沿用上一有效输出并计数，
  连续超时是 governor 的接管条件之一；
- **故障注入在信号层**：位于总线读写与控制计算之间，注入的延迟叠加真实总线
  延迟的尾部——出题人是物理，不是脚本。

## 3. 硬件 BOM 与环境说明

| 部件 | 推荐 | 量级 | 备注 |
|---|---|---|---|
| 电机 + 驱动 | moteus n1 + RS485（或 pi3hat 方案） | ≈ ¥1500 | 内置 1kHz+ 电流/位置环，编码器自带 |
| 摆杆 | 3D 打印杆 + 可挂配重块 | ≈ ¥100 | 配重块是第五幕的道具 |
| RT 盒 | NUC 或树莓派，刷 PREEMPT_RT Linux | ¥1000–2000 | 专用设备，见下方"两个坑" |
| Host | 现有开发笔记本即可 | — | 只跑训练与控制台 |

**两个坑（重要）**：

1. **WSL2 不能当 RT 盒**：无 PREEMPT_RT 内核、USB 直通延迟不可控。当前工作站的
   WSL2 环境只承担 Host 侧（训练、可视化）；1kHz 循环必须跑在独立的 PREEMPT_RT 设备上。
2. **不要用 Dynamixel 走 USB 跑 1kHz**：USB-CDC 延迟抖动会把 demo 的"确定性"变成
   笑话。选有确定性总线的方案（RS485 帧同步 / EtherCAT）。

## 4. 软件栈与数据流

| 层 | 选型 | 说明 |
|---|---|---|
| 训练 | MuJoCo + Gymnasium + SB3 PPO | 复用本仓库现有栈；策略输入 obs，输出目标角度/力矩 |
| 策略部署 | ONNX Runtime（timeboxed 封装） | 超时检测 + 有效输出保持 + 回退握手 |
| RT 运行时 | PREEMPT_RT Linux，SCHED_FIFO 1kHz 循环 | 循环含"读→检→算→写"全链，overrun 计数 |
| 低层控制 | 关节 PD（1kHz），governor 仲裁 | 包络检查在 PD 之前 |
| 回退控制器 | 能量法摆-down + 抱闸 | v1 简单可证，RoA 理论留研究线 |
| 故障注入 | 信号层中间件 | 延迟/丢帧/力矩衰减/（物理）配重 |
| 控制台 | Host 侧 Python（现有栈即可） | 实时曲线、抖动统计、重放、报告 |

信号字典（demo 版）：`timestamp, theta, theta_dot, torque_cmd, policy_target,
policy_latency_ms, envelope_ok, governor_state, injected_fault_id`。
每个信号带单调时间戳——第五幕报告的追溯基础。

## 5. 演示脚本（五幕）

| 幕 | 内容 | 屏幕上打出的数字 | 证明什么 |
|---|---|---|---|
| 1 常态 | RL 策略起摆 → 直立保持 | 1kHz 实测抖动 < 100µs；overrun = 0 | 硬实时 |
| 2 温和退化 | 注入 +5ms 延迟，摆杆晃而未倒 | "延迟↔稳定裕度"曲线第一个数据点 | 鲁棒性可测量 |
| 3 极端故障（无保护） | +30ms 延迟或编码器丢帧 → **策略发散、摆杆猛甩** | 红色告警 + 发散时间线 | 失败必须真实发生 |
| 4 同场景 + governor | 同样的发散，越界瞬间接管，能量法缓缓放倒、抱闸 | **越界→接管 4.2ms**；与第 3 幕左右分屏 | runtime assurance |
| 5 归因彩蛋 | **当众往摆杆夹配重块**（物理改变模型）；RT 模型误差证书预测衰减，实测曲线叠加；一键重放生成报告 | 预测 vs 实测两条曲线；完整时间线报告 | 模型层 + 追溯 |

第 3 幕是灵魂：失败必须真实发生，否则第 4 幕的拦截没有对照物。
第 5 幕是给技术观众的钩子：真机上摔的那次永远说不清；这里每次都有司法级记录。

## 6. 卖点与演示环节对照

| MBD 卖点 | 证明环节 | 它可能的失败方式（= 证明力来源） |
|---|---|---|
| 硬实时 / 确定性 | 第 1 幕 | 循环真的会 overrun（计算与墙钟赛跑） |
| 故障注入真实 | 第 2/3 幕 | 注入延迟叠加总线真实尾部，不是脚本数字 |
| Governor 兜底 | 第 4 幕 | 可能拦晚、回退自己不稳、拦截瞬间 overrun |
| 模型编译 + 误差证书 | 第 5 幕 | 预测与实测可能背离（背离了也是信息） |
| 归因 / 追溯 | 第 5 幕 | 每次故障带完整确定性时间线 |
| 分层部署（100Hz/1kHz） | 全程 | 与真实机器人控制架构同构 |

## 7. 验收指标

| # | 指标 | 目标 |
|---|---|---|
| 1 | 1kHz 循环抖动 | < 100µs（PREEMPT_RT x86 档） |
| 2 | overrun 率 | = 0（30 分钟连续运行） |
| 3 | 越界→接管延迟 | < 5ms |
| 4 | 接管后稳定时间 | < 2s 到达安全态（悬挂 + 抱闸） |
| 5 | A/B 复现 | 同一注入场景，无保护甩杆 / 有保护平稳，一键复现 ≥ 10 次 |
| 6 | 配重实验 | 误差证书预测的衰减趋势与实测方向一致（v1 为统计版，不要求幅值精确） |
| 7 | 报告生成 | 第 5 幕重放自动产出含全信号时间线的报告 |

## 8. 实施顺序（约 3 周）

| 周 | 内容 | 出口条件 |
|---|---|---|
| 1 | 纯仿真版全链路（RT-SIL 档）：PPO 训练 → ONNX → PREEMPT_RT 盒上的仿真循环 + governor + 注入框架 | 软件骨架在仿真时间下全部跑通；**内部调试用，不对外演** |
| 2 | 接真电机：调 1kHz 循环与抖动；跑通第 1–2 幕 | 验收指标 1/2 达标 |
| 3 | governor 阈值整定；第 3–5 幕排练；自动报告 | 验收指标 3–7 全部达标 |

附带的工程收益：第 1 周结束即得到"降级 demo"（RT-SIL 版），硬件未到时可用于
演示软件骨架——但对外演示永远只用第 3 周的版本。

> 任务级分解（人天粒度、含依赖关系与逐项验收标准）见
> [`robotics-mbd-tasks.md`](./robotics-mbd-tasks.md) **D 系列**。

## 9. 与现有仓库的衔接

| 现有资产 | 在 demo 中的角色 |
|---|---|
| `examples/models/pendulum.xml` | 第 1 周仿真训练的 MJCF 起点 |
| `examples/05_train_rl_ppo.py`（SB3 PPO + Gymnasium 栈） | 策略训练模板，封装为单摆 env 后复用 |
| `mujoco_menagerie/unitree_go2/` | 不参与本 demo；是 M1 正式版（四足关节模组台架）的机型 |
| `verify_mujoco.py` | RT 盒环境冒烟测试模板 |

后续产出物建议放 `examples/output/`（训练产物）与独立 `demo/` 目录（RT 侧代码），
遵循仓库"生成物不进版本库正文"的约定。

## 10. 已知风险与规避

| # | 风险 | 规避 |
|---|---|---|
| 1 | moteus 供货 / 总线调试耗时 | 备选：pi3hat 方案；或先用任意电机 + 降频（500Hz）保排期 |
| 2 | 第 3 幕"甩得不够戏剧化" | 预先扫参数找出策略确定发散的注入组合；排练时固定该组合 |
| 3 | governor 阈值过松/过紧 | 第 3 幕的失败数据反过来标定阈值（失败数据即资产） |
| 4 | 配重实验预测方向失准 | 诚实展示背离并标注适用范围——背离本身演示了误差证书的价值 |
| 5 | 观众质疑"单摆太简单" | 叙事预案：架构与整机同构（100Hz/1kHz、governor、信号字典），摆杆只是物理后果的最小载体 |
