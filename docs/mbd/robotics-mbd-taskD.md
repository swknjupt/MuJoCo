| 7 | **本机 RT 内核最坏延迟天花板（Max ≈ 1.7–2.2ms）——SMI 归因已被推翻，真凶疑似 RT 特有软件效应** | 实测链：generic cyclictest Max 657µs / RT cyclictest Max 1733–2203µs（4 次复现）/ **generic 上 hwlatdetect 600s 零硬件停顿（<100µs，0 采样）**→ 排除 SMI/固件停顿。RT 上的 ~2ms 尖峰为软件层效应（首要嫌疑：优先级继承提升的 IRQ 线程竞争），**存在修复可能**（隔离核 + IRQ 亲和性重绑，留 D1.4/D2.6 调优时验证）。验收口径维持统计式：P99.99 < 50µs、Max < 5ms、尖峰逐拍留痕 |

| 9 | **GRUB→RT 引导缺陷为最终判定，永久放弃 GRUB 直启 RT；RT 会话管理通道 = 网线（首选）/USB 网卡；本机禁止热重启进 RT** | 穷尽实验后定论：断电清零 CNVi 状态后 GRUB 直启 RT 仍卡死（排除固件脏状态论）；GRUB→RT 6 试 5 卡 vs kexec→RT 2/2 成功、GRUB→generic 100% 成功。真因锁定在 GRUB 装载 6.8.1 RT 内核/initrd 的环节与固件的兼容性，远程无法进一步定位。**SOP 铁律：本机需要重启时一律 `poweroff` + 重新上电（热重启会累积 CNVi/ME 脏状态，最终导致 WiFi 探测超时 -110 网卡消失）；进 RT 一律 kexec** |
| 10 | **自动化循环（批处理架子）的纪律：首次运行必须用无害任务冒烟；hwlatdetect-on-RT 永久弃用** | 2026-11-09 两次实战教训：① 任务无内层超时会拖死循环（已修：660s 内层 + 1800s 看门狗）；② **首次实战直接排真实任务（hwlatdetect-on-RT），结果系统挂死**——正确流程应为先排 60s 短 cyclictest 验证"进 RT→跑→安全回 generic"全回路，再上真实任务。hwlatdetect 的关中断探测疑似与 RT 内核线程化中断冲突，永久弃用；批处理服务已停用（disable），待 D2.6/D3.x 有真实批量需求时按冒烟纪律重新启用 |
| 11 | **governor 角度包络采用 armed 语义** | 正常起摆必须从悬垂穿越 100° 到倒立；若 `|θ|>100°` 无条件触发，第 1 幕会误接管。修订为：速度/力矩/失联/overrun 始终监控；只在曾进入倒立 ±30° 后，以倒立偏差 >60° 判跌落。新增回归测试确保正常穿越不误触发 |
| 12 | **故障注入与安全监控使用双通道** | 注入只污染策略/PD 的“功能通道”；governor 始终读取原始编码器“安全通道”。否则编码器冻结会让策略和 governor 同时失明，runtime assurance 失去独立保护意义 |
| 13 | **正常批处理结束后可自动 `systemctl reboot` 回 generic；故障/失联恢复必须人工 `poweroff` + 上电** | 已多次验证批处理任务结束后 systemd 自动回 generic 可用。若 T14 卡死、失联或疑似 CNVi/ME 状态异常，禁止继续热重启，改做完整断电重启 |
| 14 | **真机 Demo 分两阶段：先 MBD 最小垂直切片，再完整 MBD Demo** | 电机到货后先用 60° 自由摆建立最小可信模型，再用同模型驱动 governor 制动并比较仿真/真机；不加载 RL。DL1–DL5 通过后才进入 D2.3–D2.6/D3.1–D3.7 |

## 2. Task D 的目标：三重验证

Task D = 在一个真实电机 + 一根摆杆上，搭出机器人 MBD 平台的微缩版。
阶段 1 约 4 人天，先证明“模型→控制→真机→对比”闭环；阶段 2 约 27 人天，再回答三个完整问题：

| 维度 | 问题 | 量化判据 |
|---|---|---|
| **通路实验** | 全链路能否打通：训练 → ONNX → RT 盒 → 1kHz 循环 → 真电机 → 日志回传 | 五幕剧第 1–4 幕在真机上走通 |
| **可行性实验** | 三个核心假设是否成立 | ① 策略可训（起摆成功率）② 推理 P99 < 10ms ③ 商品硬件抖动 < 50µs（不需要 30 万的 Speedgoat） |
| **证据实验** | 能否拿到对外说的实测数字、A/B 对比是否有说服力 | "越界→接管 < 5ms"实测 + 复现 ≥ 10 次 + 自动报告 |

**范围外（明确不做）**：整机演示、灵巧手操作、感知闭环、任何形式的产品化代码。

### 2.1 两阶段定义

| 阶段 | 目标 | 包含 | 不包含 |
|---|---|---|---|
| **阶段 1：D-Lite** | MBD 最小垂直切片 | 自由摆仿真/真机对比、少量参数辨识、模型驱动 governor 制动、对比报告 | RL、ONNX、起摆、平衡、配重、完整模型辨识 |
| **阶段 2：完整 Task D** | 验证完整 MBD 方法论 | RL 起摆/平衡、延迟与丢帧、A/B、配重、五幕 | 无 |

阶段 1 的通过标准是进入阶段 2 的硬门控。阶段 1 不是完整 Demo 的替代品。

## 3. 系统架构

### 3.1 运行时架构

```
┌─ Host（WSL2 开发机，非实时）────────────────────────┐
│  训练（MuJoCo+SB3）· 控制台/可视化 · 报告生成         │
└──────────────┬──────────────────────────────────┘
               │ SSH/局域网（允许抖动）
┌──────────────▼─ RT 盒（T14, Ubuntu+PREEMPT_RT）─────┐
│                                                     │
│  核1【隔离, SCHED_FIFO 99】 1kHz 主循环              │
│  ┌─────────────────────────────────────────────┐   │
│  │ 读编码器 → [注入框架] → 包络检查 → PD → [注入] → 写力矩 │   │
│  └─────────────────────────────────────────────┘   │
│   ↑无锁共享内存(带时间戳)          ↓违约事件          │
│  核2【SCHED_FIFO 80】            Governor 状态机     │
│  ┌──────────────────┐          NORMAL→FALLBACK→SAFE │
│  │ 100Hz timeboxed   │──────────┘                   │
│  │ ONNX 推理线程      │  回退控制器(能量法+抱闸)        │
│  └──────────────────┘                               │
│  核0: 日志搬运/SSH/网络（禁止碰核1）                    │
└──────────────┬──────────────────────────────────┘
               │ RS485（确定性，几十厘米）
      ┌────────▼────────┐
      │ moteus 电机+摆杆 │ 内置保护：电流/温度/力矩限制
      └─────────────────┘   ← 系统最后一道防线
```

三条铁律：

1. **1kHz 拍内只装"计算量恒定、上界可证"的代码**（读 I/O、几个比较、PD 两次乘法）；
2. **NN 永不进 1kHz 拍**：在核 2 以 100Hz 跑，主循环只读"最近一次有效输出"（latest-value buffer），快慢不管、保鲜期 30ms、连续超时交给 governor；
3. **违约必记账**：overrun 与推理超时逐拍计数，屏幕可见，是 governor 的触发条件之一。

### 3.2 信号字典（demo 版，9 信号）

| 字段 | 单位 | 频率 | 说明 |
|---|---|---|---|
| `timestamp` | µs（单调时钟） | 1kHz | 一切追溯的基准 |
| `theta` | rad | 1kHz | 摆角实测 |
| `theta_dot` | rad/s | 1kHz | 角速度实测 |

| `policy_target` | rad | 1kHz(快照) | 最近一次有效策略输出 |
| `policy_latency_ms` | ms | 100Hz | 推理耗时 |
| `envelope_ok` | bool | 1kHz | 包络检查结果 |
| `governor_state` | enum | 事件+1kHz | NORMAL/FALLBACK/SAFE |
| `injected_fault_id` | enum | 事件 | 当前注入的故障类型 |

## 4. 任务分解与工作内容

### D0 环境恢复（补充任务，任务清单外的先行项）

- **工作内容**：恢复 `.venv`（`uv venv && uv pip install -r requirements.txt`）；跑
  `.venv/bin/python verify_mujoco.py` 冒烟；确认 `examples/05_train_rl_ppo.py`
  的依赖完整（只需 import 通过，不必完整训练）。
- **产出**：可用的训练环境。
- **验收**：`verify_mujoco.py` 全绿；SB3 导入无报错。

### 4.1 第一周（D1.x）：RT-SIL 纯仿真全链路——"在模拟器里练车"

#### D1.1 封装单摆 Gymnasium env

- **实现要点**：
  - **环境结构必须镜像部署架构**——这是最重要的设计约束：策略以 100Hz 输出**目标角度**，
    env 内部以细步长（1kHz 等效）跑 PD 跟踪。即 `policy_freq=100, pd_freq=1000`，
    每次 `env.step()` 内部做 10 次 PD 子步（decimation=10）。这样训练出的策略
    与部署时的"100Hz 出目标 + 1kHz PD 执行"天然同构；
  - 观测建议：`[cosθ, sinθ, θ̇, 目标偏差]`（角度用 cos/sin 避免±π 跳变）；
  - 奖励：直立项 − 角度偏差 − 速度惩罚 − 力矩惩罚；终止：|θ| > 60°（与包络一致）
    或超时；
  - 预留**观测延迟参数**（`obs_delay_ms`）：训练时可配置，为 D3 的退化实验做接口准备；
  - 起点模型 `examples/models/pendulum.xml`，必要时调整执行器参数使其与所选电机量级接近。
- **产出**：`demo/envs/pendulum.py`（或并入 examples 结构，自行判断后记录决策）。
- **验收**：`check_env` 通过；随机动作下动力学正常；手动给定目标角时内部 PD 可稳定跟踪。

#### D1.2 PPO 训练至收敛

- **实现要点**：复用 `05_train_rl_ppo.py` 的栈；MlpPolicy（2×64 即可）；先小规模
  调奖励结构（起摆需要探索，必要时先训"保持平衡"再训"起摆+保持"两阶段）。
- **验收**：10 次评估全部起摆成功并保持 ≥ 30s。

#### D1.3 导出 ONNX + 推理延迟基准

- **实现要点**：SB3 policy → torch → ONNX；**基准必须在目标硬件上测**
  （RT 盒 CPU，不是开发机，更不是 GPU）；测 1000 次取 P50/P99/Max。
- **验收**：RT 盒 CPU 上 P99 < 10ms（小 MLP 预期 < 1ms，余量巨大）。

#### D1.4 PREEMPT_RT 1kHz 循环骨架

- **实现要点**（主循环伪代码）：
  ```python
  # C 实现同理；要点是每个 API 的选择都有实时性理由
  sched_setscheduler(SCHED_FIFO, prio=99)     # 最高优先级
  mlockall(MCL_CURRENT|MCL_FUTURE)            # 锁内存，禁止缺页
  pin_to_cpu(1)                                # 隔离核
  next = clock_gettime(MONOTONIC)
  while True:
      next += 1ms
      t0 = now()
      读编码器 → 包络检查 → PD → 写力矩        # 全部 < 200µs
      t1 = now()
      if t1 > next: overrun_count += 1        # 违约记账
      clock_nanosleep(ABSTIME, next)           # 绝对时间睡眠，不累积误差
  ```
  第一周 Plant 用仿真回调（同进程或共享内存），但**循环本身对墙钟真跑**；
  空载/带载两档测试。
- **验收**：空载抖动 < 50µs，30 分钟 overrun = 0（在 RT 盒上）。

#### D1.5 Governor 状态机 v0

- **实现要点**：
  - 状态：`NORMAL → FALLBACK → SAFE`（单向 + 迟滞，一旦 FALLBACK 不自动回到 NORMAL，
    人工复位才回）；
  - 触发条件（任一）：|θ|、|θ̇|、|τ| 越限；策略输出过期 > 30ms；overrun 连续 > 3 拍；
  - FALLBACK 动作：切换力矩源为回退控制器——**能量法**：施加与速度反号、
    与能量成正比的阻尼力矩，把摆缓缓放回下垂位；能量低于阈值 → SAFE（抱闸/保持阻尼）；
  - 回退控制器必须是纯确定性代码（无分配、无外部调用）。
- **验收**：仿真注入发散场景（强制策略输出大幅错误值），越界→接管 < 5ms（仿真时间），
  接管后 2s 内到 SAFE。

#### D1.6 Timeboxed 推理壳

- **实现要点**：独立线程（核 2，SCHED_FIFO 80），10ms 周期；ONNX 推理包裹超时看门
  （推理本身超时则沿用旧输出并计数 `timeout_streak`）；输出写入**无锁 latest-value
  buffer**（双缓冲 + 原子索引 + 单调时间戳），主循环只读。
- **验收**：人为注入推理阻塞（sleep），壳按预期降级（沿用旧值、计数增加），
  主循环无任何阻塞或延迟变化。

#### D1.7 信号层注入框架

- **实现要点**：位于 I/O 与控制计算之间的可组合中间件；三类注入：
  ① 延迟（环形缓冲回放 k ms 前的读数）② 丢帧（零阶保持）③ 力矩衰减（输出乘系数）；
  注入计划**种子化**（同一种子完全复现）——复现性是第五幕的生命。
- **验收**：三类注入独立开关正常；同一种子两次运行的时间线逐拍一致。

#### D1.8 第一周集成（RT-SIL 联调）

- **工作内容**：D1.4–D1.7 全部组件 + 仿真 Plant 接成一个进程组；跑通第 1/2/3/4 幕
  的仿真时间版本；产出抖动基准报告。
- **验收**：五幕中 1/2/3/4 幕在仿真时间下走通；**降级 demo（RT-SIL 版）成型**——
  仅内部调试用，永远不对外演示（原则：仿真世界里没有"迟到"这个概念，
  对外证据必须出自真机）。

### 4.2 阶段 1：D-Lite 单摆 MBD 最小垂直切片

> 入口：D2.1 完成，D2.2 真机 RS485 通过。阶段 1 不加载 ONNX、不使用训练策略。
> Governor 使用独立演示配置 `demo/configs/stage1_brake_governor.json`。

#### DL1 最低机械安装与安全准备

- 安装电机、摆杆、枢轴、刚性底座和透明防护。
- 增加 60° 机械挡块或释放夹具，确保每次释放角为悬垂方向 `60° ± 2°`。
- 确认编码器零位、正方向和电源急停；不要求完整惯量/摩擦辨识。
- **验收**：重复放置 10 次角度在 ±2°；线缆不会卷入，急停可立即切断动力。

#### DL2 自由摆仿真基准与真机采集

- 仿真和真机均从悬垂方向 +60°、角速度 0 释放。
- 不启用 governor，电机保持零力矩/滑行，不进入抱闸。
- 至少采集 3 个完整摆动周期或 30 秒。
- 阶段 1 CSV 使用七信号：`timestamp_us / theta / theta_dot / torque_cmd /
  envelope_ok / governor_state / injected_fault_id`。
- **验收**：真机数据 1kHz、时间戳单调、无掉线；仿真生成相同格式轨迹。

#### DL3 等效参数辨识

- 从自由摆周期估计 `I/(m·l_c)`，从相邻峰值估计阻尼/摩擦。
- 质量由秤重获得，质心由几何测量获得；力矩比例/延迟由电机阶跃或后续制动数据修正。
- 更新 `demo/configs/stage1_pendulum_model.json`，记录参数来源和适用范围。
- **验收**：仿真/真机周期相对误差 `≤10%`；角速度峰值误差 `≤20%`；
  摆动衰减方向一致。

#### DL4 模型驱动的仿真/真机 A/B 制动

四组运行使用相同初始状态和模型参数：

- 仿真 A：governor 关闭，无制动；
- 仿真 B：governor 开启；
- 真机 A：governor 关闭，零力矩滑行；
- 真机 B：governor 开启。

阶段 1 Governor 配置 `demo/configs/stage1_brake_governor.json`：

- `theta_dot_max=3.5rad/s`（为 `60° ± 2°` 释放误差保留触发余量）；
- `fall_threshold=45°`；
- `k_energy=0.4`；
- `c_visc_min=0.6`；
- `kp_hang=15`；
- `e_safe_threshold=0.3`；
- `tau_fallback_max=4.5N·m`。

**验收**：真机 A 持续自由摆动；真机 B 速度越界→接管 `<5ms`、接管→SAFE `<2s`、
最终偏差 `<5°`、全程 `abs(τ) ≤ 5N·m`。仿真/真机接管时间差
`≤100ms` 且相对差 `≤20%`。

#### DL5 10 对复现与 MBD 对比报告

- 使用相同释放夹具运行 10 对真机 A/B；奇偶对交替 A→B/B→A 顺序。
- 保存每次 CSV、`run_manifest.json`、模型配置和 Governor 配置哈希。
- 对比仿真 A/B、真机 A/B，以及仿真 B 与真机 B 的周期、峰值、接管和 SAFE。
- 复用 D3.6 报告基础设施，新增叠加曲线、RMSE、事件差和参数表。
- **验收**：10/10 对 A 无主动安全态、B 均完成接管并 SAFE；overrun=0；
  一键生成 MBD 对比 HTML。

阶段 1 失败处理：

- 首次上电先做低速 ±10° 小幅摆动，不允许直接做 60° 高速释放；
- 任一次超过力矩/温度/电流限制或出现接线异常，立即停机；
- 接线、零位或通信未确认前不进入 DL2；
- 周期误差超过 10% 或衰减方向不一致时，不得用当前模型宣称 MBD 预测成立；
- 阶段 1 未通过不得加载阶段 2 RL 策略。

## 5. 验证策略

### 5.1 阶段 1 真机验收

| 指标 | 目标 |
|---|---|
| 初始释放角 | `60° ± 2°` |
| 自由摆周期 | 仿真/真机相对误差 `≤10%` |
| 峰值与衰减 | 角速度峰值相对误差 `≤20%`；衰减方向一致 |
| governor 关闭 | 持续自由摆动，不进入 SAFE |
| 自动接管 | 真机角速度越界后 `<5ms` |
| 仿真/真机接管时间 | 差值 `≤100ms` 且相对差 `≤20%` |
| 接管→SAFE | 真机 `<2s` |
| 最终偏差 | `<5°` |
| 力矩 | `abs(τ) ≤ 5N·m` |
| A/B 复现 | `10/10` 对一致 |
| RT overrun | 所有运行均为 0 |
| 报告 | 一键生成仿真/真机叠加曲线、RMSE、事件差和参数表 |

### 5.2 阶段 2 分层验证（每层通过才进下一层）

```
L1 单元级（仿真时钟, 开发机）: 各组件逻辑正确性
L2 集成级（墙钟, RT 盒, 仿真 Plant）: RT-SIL, 时序数字真实
L3 真机级（墙钟, 真电机）: 物理后果真实
L4 演示级（彩排, 有观众时间压力）: 全剧本稳定复现
```

核心原则：**每一层的证据只能由该层及以上产出**——时序数字必须出自 L2+，
说服力必须出自 L3+。仿真层的任何表现不构成对外证据。

### 5.3 五幕剧与验证判据（L3/L4 的脚本）

| 幕 | 内容 | 通过判据 |
|---|---|---|
| 1 | 策略起摆 + 直立保持 | 屏显：抖动实测值、overrun=0 |
| 2 | 注入 +5ms 延迟 | 摆晃不倒；记录"延迟↔稳定裕度"曲线第一个点 |
| 3 | 极端注入，governor 关闭 | **策略发散、甩杆**（必须真实发生，这是对照组） |
| 4 | 同场景，governor 开启 | 越界→接管实测 < 5ms；与第 3 幕分屏对比 |
| 5 | 当众夹配重 + 一键重放报告 | 预测/实测曲线方向一致；报告自动生成 |

### 5.4 阶段 2 最终验收指标（完整 Demo 的完成定义）

1. 1kHz 抖动 < 100µs（带载）；2. overrun = 0（30 分钟）；3. 越界→接管 < 5ms；
4. 接管→SAFE < 2s；5. A/B 复现 ≥ 10 次；6. 配重预测方向一致；
7. 报告一键生成。**任一不达标 = Demo 未完成。**

### 5.5 失败处理原则

**失败数据即资产**：第 3 幕的发散轨迹是 D3.2 阈值标定的输入；L2/L3 的每次 overrun
都是时序报告的素材。禁止"调到好看为止"——记录真实值，指标不达标就修根因
（改配置/降负载/查 SMI），不留不明原因的尖峰。

## 9. 通俗版：Task D 到底在干什么

（本章写给不接触实现的读者；比喻贯穿始终：**驾校**。）

### 9.1 角色对照

| 系统部件 | 驾校里的对应物 | 一句话性格 |
|---|---|---|
| RL 策略（神经网络） | 学员司机 | 聪明，会起摆会适应，但你不敢完全信他 |
| 1kHz 循环 + PD | 方向盘和手脚 | 笨但勤快，每毫秒微调一次 |
| Governor | 教练的副刹车 | 全程盯着，学员乱打方向就踩 |
| 故障注入 | 教练故意捣乱 | 蒙眼睛、拖口令，逼学员犯错 |
| 电机内置保护 | 车自带手刹 | 连教练都失灵时的最后一道保险 |

### 9.2 三周在干嘛

- **第一周：模拟器里练车。**把"每毫秒微调的程序"、"盯学员的眼睛"、"捣乱工具"
  全写好，对着一个假的摆把整套流程走通——模拟器里摔了不心疼，改起来快。
- **第二周：上真车，先不捣乱。**软件接到真电机上，先让学员正常开——
  立得起来吗？稳吗？车本身手抖不抖（抖动实测）？这周结束拿到第一批真数字。
- **第三周：正式捣乱，测副刹车。**教练开始蒙眼拖口令，故意让学员失控：
  先**不踩**刹车，让大家看到失控多吓人（甩杆那一幕）；再**踩**，让大家看到
  5 毫秒内接管、平稳停下。最后练成一套 8 分钟的固定表演。

所以 Task D 一句话：**在真电机上故意制造事故，验证"学员会犯错，
但教练的副刹车永远踩得下去"**——既是看这套东西搭不搭得起来（可行性）、
每一环接不接得上（通路），更是拿一批能对外说的实测数字、排一场有说服力的戏（证据）。

### 9.3 "Linux 笔记本不是真硬实时"怎么办（三句话版）

1. **要干的活太轻**：每 1ms 只干一件几微秒的小事，预算只用了 5%——
   相当于要求一个人每秒眨一次眼。装上实时补丁后实测半小时一次盹都没打过
   （cyclictest 验收 = 用体检报告代替永不下保证）；
2. **打个盹也有考勤**：迟到计数器逐拍记账，屏幕可见。半小时 180 万拍晚几拍，
   摆杆毫无感觉；只有**连续**迟到教练才踩刹车；
3. **最后的保险不在笔记本上**：就算笔记本整个卡死，电机自己的保护电路还在
   （手刹）。最坏结果是演示暂停，不是设备烧毁。产品化时这道防线会正式移到
   FPGA/电机芯片（可证明的硬实时），架构里已留好位置。

### 9.4 给观众的标准应答（三问三答）

- **"单摆太简单了吧？"** → 架构与真机器人完全同构（100Hz 策略 + 1kHz 低层 +
  governor + 故障注入），摆杆只是物理后果最便宜的载体；电机甩动证明的才是平台。
- **"为什么不用 Speedgoat/dSPACE？"** → 它们卖的是"确定性打包"，30 万起；
  我们验证的是同一套方法论能在商品硬件上复现，这是产品定价和普及的前提。
- **"Linux 是不是假实时？"** → 是"工程级"而非"证明级"：用测量验收代替数学证明，
  违约逐拍记账、governor 兜底、最后一道防线在电机驱动——我们不承诺永不超时，
  我们承诺超时无处藏身。
